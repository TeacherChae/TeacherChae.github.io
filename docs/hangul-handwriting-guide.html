Hangul Handwriting · Stroke-Order Drawing

한글 이름 손글씨 획순 드로잉
수작업 방법론

폰트 외곽선이 아니라 펜이 지나가는 중심선(centerline)을 한 획씩 그리고, 획순대로 순서를 매겨 한 글자가 손으로 써지듯 애니메이션하는 방법 — 처음부터 끝까지.

왜 중심선인가 한 획 = 하나의 path 획순 분해 ▶ 라이브 데모 붓 두께 기법 애니메이션 원리 전체 워크플로우 C · 영상(AE Write-on) 체크리스트

1 왜 "중심선"을 그려야 하나

영문 필기체는 글자가 이어져서 외곽선만 따라 그려도 쓰는 느낌이 납니다. 하지만 한글은 획이 많고 닫힌 외곽이라, 폰트 외곽선을 그리면 글자 테두리를 도는 느낌이 됩니다. 펜으로 쓰는 느낌을 내려면 획의 중심선이 필요해요.

2 "한 획 = 하나의 path", 그리고 진행 방향

펜을 떼지 않고 긋는 선 하나가 곧 하나의 <path>입니다. 점을 찍는 순서가 펜 진행 방향이고, 그 방향이 애니메이션에서 그려지는 방향이 됩니다.

한 글자 안에서 여러 획을 그렸다면, 레이어/배열 순서를 획순대로 정렬해 두세요. 이 순서가 그대로 "1번 획 → 2번 획 → …" 애니메이션 순서가 됩니다.

3 획순 분해 (이름 6글자)

각 음절을 자모로 쪼개고 표준 획순으로 번호를 매깁니다. 위→아래, 왼→오, 가로 먼저, 초성→중성→받침이 기본 규칙이에요.

음절자모 분해획 구성 (초성 → 중성 → 받침)
이ㅇ + ㅣㅇ(원) → ㅣ(세로) — 2획
주ㅈ + ㅜㅈ(가로·좌삐침·우삐침) → ㅜ(가로·세로) — 5획
경ㄱ + ㅕ + ㅇㄱ → ㅕ(세로·짧은가로2) → ㅇ받침 — 5획
채ㅊ + ㅐㅊ(점·가로·삐침2) → ㅐ(세로·짧은가로·세로) — 7획
건ㄱ + ㅓ + ㄴㄱ → ㅓ(세로·짧은가로) → ㄴ받침 — 5획
희ㅎ + ㅢㅎ(점·가로·원) → ㅢ(세로·가로) — 6획

합계 대략 30획 내외. 붓 강약(가변폭)으로 가면 획당 면(shape)까지 그려야 해서 path 수가 더 늘어납니다.

▶ 라이브 데모 — 획순대로 그려보기

아래는 중심선 + 획순 stagger로 글자가 써지는 모습을 그대로 시연한 것입니다. (획 모양은 개념 설명용 근사치 — 실제 작업에선 4단계 트레이싱으로 더 자연스럽게 그립니다.)

4 (선택) 붓 두께 — 마스크 기법

균일 두께 펜은 path에 stroke-width만 주면 끝입니다. 붓처럼 굵기 강약을 주려면, 두꺼운 채움 면(shape)을 깔고 그 위를 중심선 마스크로 쓸어 점점 드러냅니다.

처음엔 균일 두께(A)로 시작해서 형태/획순을 확정하고, 만족스러우면 그때 붓 마스크(B)로 업그레이드하는 걸 추천합니다.

5 애니메이션 원리 — stroke-dashoffset / pathLength

선 하나를 "그려지게" 하는 원리는 점선(dash) 트릭입니다. 획 길이만큼의 빈 점선을 만들고, 그 간격(offset)을 길이 → 0으로 줄이면 선이 왼쪽부터 채워집니다.

실제 코드 골격 (현재 영문 구현과 동일 패턴)

// strokes = 획순대로 정렬된 path 배열
{strokes.map((d, i) => (
  <motion.path
    key={i} d={d}
    fill="none" stroke="currentColor" strokeWidth={3}
    strokeLinecap="round" strokeLinejoin="round"
    initial={{ pathLength: 0 }}
    animate={{ pathLength: 1 }}
    transition={{ delay: i * 0.18, duration: 0.4, ease: 'easeInOut' }}
  />
))}

6 전체 워크플로우 & 역할 분담

손작업(사람·디자이너)   코드(Claude)

C 대안 루트 — After Effects "Write-on" (영상으로 뽑기)

"캘리그라피 애니메이션"의 업계 표준 방식. 원리는 B(마스크 reveal)와 동일하지만, 결과가 웹 코드(SVG)가 아니라 영상이라는 점이 다릅니다. 진짜 붓 손맛을 그대로 쓸 수 있어요.

After Effects 단계

  1. 캘리그라피 준비 — Procreate/손글씨 이미지를 import 하거나 텍스트 레이어 생성
  2. 마스크 패스 그리기 — 글씨 위에 펜툴로 획순·방향대로 마스크 패스를 그림 (이게 B의 중심선 트레이싱과 같은 "노가다")
  3. Stroke 효과 적용 — 레이어에 Effect ▸ Generate ▸ Stroke, Path를 그 마스크로 지정
  4. Paint Style = "Reveal Original Image" — 스트로크가 지나간 자리에 원본 글씨가 드러나게 설정
  5. End 0% → 100% 키프레임 — 시간에 따라 획이 그려짐. 획별로 키프레임 나눠 속도 조절
  6. (선택) 붓/펜 든 손 이미지를 마스크 패스 끝점에 붙여 진짜 쓰는 것처럼
  7. 렌더 — 알파 포함으로 출력

웹에 넣을 때 (영상의 현실)

투명 배경 영상은 브라우저별로 코덱이 갈립니다.
· Chrome/Firefox/Android → VP9 알파 (WebM)
· Safari/iOS → HEVC 알파 (MP4, hvc1)
두 포맷을 <video> 의 <source> 두 개로 같이 넣어야 모든 기기에서 투명하게 재생됩니다. 
<video autoplay muted playsinline loop>
  <source src="name.webm" type="video/webm">        <!-- VP9 alpha -->
  <source src="name.mov"  type='video/mp4; codecs="hvc1"'> <!-- HEVC alpha -->
</video>

투명 영상이 부담되면 hero 사진/단색 위에 올리는 전제로 불투명 영상을 써도 됩니다(합성 이슈 회피).

7 트레이싱 체크리스트 (4번 작업용)

  • ☐ 음절마다 동일한 viewBox(예: 0 0 100 100)로 그렸는가
  • ☐ 손글씨 폰트 밑그림 위에 트레이싱해서 비율이 일관적인가
  • ☐ 중심선만 그렸는가 (외곽선/채움 아님 — 붓은 별도)
  • ☐ 한 획 = 한 path, 펜을 떼는 지점마다 분리했는가
  • ☐ 각 path의 점 순서 = 펜 방향 (시작→끝)으로 찍었는가
  • ☐ path들이 획순대로 정렬(레이어 순서)되어 있는가
  • ☐ ㅇ ㅎ 동그라미는 한 획으로 처리했는가
  • ☐ export 시 transform/group을 flatten 했는가
가장 흔한 실수
① 외곽선을 그림(채워진 글자를 트레이스) → 윤곽선 따는 느낌이 됨
② path 방향을 거꾸로 찍음 → 획이 끝에서부터 거꾸로 그려짐
③ 한 글자를 한 path로 그림 → 획순 stagger 불가

제출 형식 (저에게 넘길 때)

음절별 SVG 파일 6개(또는 전체 1개) — 각 <path>가 한 획, 획순대로 정렬, 중심선, 공통 viewBox. 넘겨주시면 정규화 → heroCalligraphyKo.js 데이터화 → 애니메이션 통합 → 프리뷰 검수까지 제가 처리합니다.
